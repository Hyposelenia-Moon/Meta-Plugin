## CI（CI v7）

`.github/workflows/ci.yml`，`push` / `pull_request` / 手动触发各跑一次，单 job、20 分钟超时、Node 24、`TZ=Asia/Shanghai`（攻略日期与缓存 TTL 都按生产时区算）。

名字里的 **v7** 指官方 action 的主版本：`actions/checkout@v7`、`actions/setup-node@v7` 的工具包以 `node24` 运行时发布；`@v4` 是按 `node20` 写的，而云端 runner 已强制用 `node24` 执行这些工具包，用 `@v4` 会刷 “Node 20 is deprecated” 警告。所以升 action 版本与把 `setup-node` 的 `node-version` 钉在 `24` 是两件事：前者治警告，后者定插件自己跑测试用的 Node。

三步：

1. `npm install --no-audit --no-fund` —— 插件目录**不提交锁文件**（`.gitignore` 约定：依赖由 bot 根的工作区统一管理），所以不缓存锁文件。
2. `npx tsc -p tsconfig.json` → `git status --porcelain --untracked-files=all -- lib` 必须为空。
   这是 **lib 入库门禁**：`src/` 改了却忘记 `pnpm build` + 提交 `lib/`，CI 直接红。
   先编译还顺手修掉一个干净检出的假红——git 不保留 mtime，`lib-fresh` 会以为 `lib/` 比 `src/` 旧。
3. `node test/run.mjs` 全量套件；缺 miao / Atlas / 浏览器的套件按上面的规则**自己跳过**，不算失败。
   失败时 `run.mjs` 会打**一条** `::error` annotation（`GITHUB_ACTIONS=true` 时才打）：标题是失败套件数，正文按套件列「名字（退出码）报错尾巴」，尾巴取最后一条失败标记起 8 行、压成一行并截断到 1200 字。
   之所以只打一条：单步最多 10 条 error annotation，失败多时逐条打会被截断；一条汇总不设上限。匿名调 `/check-runs/<job>/annotations` 就能读到套件名和断言，不用登录翻日志。

本地等价命令就是 `pnpm build && pnpm test`。失败时 job 的 Step Summary 只摘「套件：x/y 通过」与 `✗` 行，完整日志在 Run 详情里。

排查中的一个坑：用例里别写「`E:/…` 这种 Windows 盘符路径 + 断言 `file:///E:/`」。POSIX 上它会被当成相对路径（cwd 下多出 `E:` 目录），URL 变成 `file:///…/E%3A/…`，在 Linux runner 上必挂。要测「bot 外」，用 `path.resolve(root, '..', …)` 造一个绝对路径，断言 `file:///` 前缀 + 解码后的相对片段。
