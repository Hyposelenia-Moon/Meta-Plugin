# 队伍模拟：角色名录与全角色数据包

> 面向维护者：这份文档说明 `data/team-sim/` 里的产物是怎么来的、覆盖到哪、哪些是刻意没做的。
> 数据格式本身仍以 [队伍模拟-P1数据包格式.md](./队伍模拟-P1数据包格式.md) 为准。

- 相关脚本：`scripts/build-roster-map.mjs`、`scripts/extract-gcsim-frames.mjs`、`scripts/gen-roster-packs.mjs`、`scripts/gen-permanent.mjs`
- 相关产物：`data/team-sim/roster.json`（名录）、`data/team-sim/packs/<英文键>.json`（动作包）、`data/team-sim/permanent/<charId>-<武器id>-r<精炼>.json`（永久数据），三者均入库
- 中间产物（不入库，`.gitignore` 排除 `out/`）：`out/frames/<目录>.json`、`out/roster-map.draft.json`、`out/roster-packs-report.json`、`out/permanent-report.json`
- 验收：`test/team-sim-roster-packs.test.mjs`（名录与动作包）、`test/team-sim-permanent.test.mjs`（永久数据与整条管线）

## 1. 生成顺序

```powershell
node scripts/build-roster-map.mjs      # miao 中文名 + gcsim 本地化表 → 名录
node scripts/extract-gcsim-frames.mjs  # gcsim 本地源码 → out/frames/<目录>.json
node scripts/gen-roster-packs.mjs      # 名录 + 帧 + miao 天赋 → data/team-sim/packs/
node scripts/gen-permanent.mjs --preset geo-four   # miao 白值 + 人工审计效果 → data/team-sim/permanent/
```

四个脚本都只读本地文件、不联网；`MIAO_ROOT` / `GCSIM_ROOT` 环境变量可改默认路径
（默认 `D:/Program Files/Yunzai/Yunzai/plugins/miao-plugin/resources/meta-gs/character` 与 `out/gcsim`）。

## 2. 名录 `roster.json`

```ts
{ schemaVersion: 1, gameVersion: '7.1', gcsimCommit, source,
  counts: { characters, mapped, traveler, alias, 'no-gcsim' },
  characters: [{ charId, cn, keys: string[], dir, element, weapon, star, status, note? }] }
```

身份链全程离线、只做精确匹配：

```
miao 中文名 ←(names.dm.json 的 Chinese.character_names)→ gcsim 全键
            ←(pkg/shortcut/character.dm.go 的别名 → 枚举名小写)→ gcsim 目录
```

| status | 含义 | 当前数量 |
|---|---|---|
| `mapped` | 中文名精确命中，且有对应 gcsim 目录 | 113 |
| `traveler` | 空/荧，按 charId 展开成七个元素键（`aether*` / `lumine*`） | 2 |
| `alias` | 「旅行者」（20000000）与空/荧同源，不单独占用键 | 1 |
| `no-gcsim` | gcsim 本地化表里没有这个中文名（多为 7.x 新角色） | 11 |

不做拼音、不做模糊匹配、不猜别名：对不上就是 `no-gcsim`，并在 `note` 里写清原因。

## 3. 数据包 `packs/`

一份包只含普通攻击，一段一式（`<英文键>.normal-1`、`normal-2`…）：

- **命中帧**：gcsim 的 `attackHitmarks` / `attackReleases`（`[][]int` 表示同段多段命中），收尾帧取
  `frames.InitNormalCancelSlice(..., ANIM)` 的 `ANIM`；源码里的 `11 + windup`、`118-32-17` 这类常量算式按包内 `const` 求值，求不出来就留空。
- **倍率**：miao `talentData` 的「N 段伤害」天赋 10 级（索引 9，`156.62` 这种百分数 ÷100），与 §16 的录入口径一致。
- **同段多命中**：gcsim 把一段拆成多个命中帧时（香菱 N4 的 5/15/24/29 帧、钟离 N5 的 4 帧），「N 段伤害」是**整段合计**，
  逐帧倍率取 miao 的「N段伤害2」：等值的写成 `[27.88, 4]`（倍率 + 重复次数），不等的逐帧展开（胡桃 N5 `[59.36, 62.8]`）。
  展开后的合计必须与整段对上，对不上就退回整段均分并在报告里记一条；当前 74 个多段动作全部按拆分行还原，没有用到均分。
  抽帧侧的倍率只用来核对这一条（gcsim 的 `zz_*.dm.go` 注释直接写 `4-Hit DMG: {3}*4`），不作为包内倍率来源。
- **绑定条件**：天赋行数与 gcsim 命中段数必须相等，不等即整人不落包，记进 `out/roster-packs-report.json`。
- **元素**：只有法器角色的普攻天生带元素；单手剑/双手剑/长柄/弓在 gcsim 里写出的 `Element` 多是附魔态
  （雷神 Q、宵宫 E、重云 E、达达利亚 E…），一律按物理落包，并在报告里记录。
- **末帧命中**：gcsim 允许命中帧等于收尾帧（如娜维娅 N3），内核要求命中帧严格早于动作结束，这类动作顺延一帧并记录。

当前覆盖：`mapped` 113 人里 **112 人**有包（465 个自动动作、549 个命中，其中 74 个动作同段多命中）。缺的一人是**凝光**：她的普攻按左右手状态交替、
天赋表也只给单行「普通攻击伤害」，不在这套自动绑定的能力范围内，测试里显式列为例外。

## 3.1 人工核对动作（`data/team-sim/curated/`）

自动生成只覆盖普攻。战技/爆发的手工数据放在 `data/team-sim/curated/<英文键>.json`，由 `gen-roster-packs.mjs` 合并进同一个包：

- 动作键与自动生成的普攻冲突、或 `action.actorId` 不等于包名，脚本直接 `exit 1`——不搞「后写覆盖」。
- 子代理产出的草稿用 `node scripts/merge-eq-drafts.mjs out/eq-drafts/batchN.json` 合并：脚本按 roster 的 `keys[0]` 统一 `key` / `actorId` / 动作 id（gcsim 目录名可能不同，如 `kazuha` → `kaedeharakazuha`），并把动作内的 notes 提升到文件根级。
- 同一份 curated 只含 `key`、`gameVersion`、`source`、`notes`、`actions`；`notes` 会并入报告里的近似项，说明哪些部分没建模。

**动画后的主伤害怎么处理（第五批起的规则）**：gcsim 里有些动作的主伤害在「可行动帧」之后才落地（奥黛塔 Q 的 128/140/144 帧、雷电将军 E 的 51 帧）。如果按动画时长截断，这些伤害会被内核在下一个动作开始时取消——奥黛塔会丢掉约 76% 爆发伤害。处理方式是**把 `timing.frames` 记到最后一段命中之后**（奥黛塔 145、雷神 52），并在 `notes` 里写明这是已知偏差；场地/召唤物的后续跳伤仍按约定截断（久岐忍爆发只留第 1 段）。
第六批补了一条界限：只有**延迟 ≤30 帧**才后移时长（丝柯克 158→159、绫人 35→36、绫人 Q 139→140、欧洛伦 41→42）；延迟更大的按场地伤害处理、不建模（莫娜 E 的爆裂在 329 帧、温迪 Q 的 20 跳、茜特菈莉的宿灵之髑）。

第一批的口径：每角色只建模 gcsim 默认分支（点按 / 荒性），长按、芒性、剑雨、灭净三业、召唤物、领域 DoT 均未建模，逐条写在各自文件的 `notes` 里。

**爆发持续段（2026-11-02 起）**：两条爆发有了「施放之后的伤害/回能」——
- `xiangling.burst`：施放后第 56 帧起每 73 帧一次旋火轮伤害（共 9 段，倍率 2.016），
  命中标 `delayed: true`，不会被下一个动作或切人取消；
- `raidenshogun.burst`：梦想一心回能，按固定帧挂 5 次、每次全队 2.5 点，
  `rechargeScaling` 表示雷神 A4（充能超 100% 的部分每 1% 加 0.6%）。
两条都按 gcsim 行为近似，不建模旋火轮绕圈命中次数、梦想一心普攻段与协同攻击频率。

倍率来自 miao 天赋 10 级（与 gcsim 的 `zz_*.dm.go` 表逐项对上），命中帧/时长/冷却/能量上限来自 gcsim `fcc117b`，
出处逐条写在每个文件的 `source` 里。一斗爆发不造成伤害（gcsim 也只做状态），因此没有 `aratakiitto.burst`。

## 4. 刻意没做的部分

- **战技 / 爆发 / 重击（自动生成）**：`scaling`（atk / hp / def）无法离线判定，自动生成不给这些动作；
  目前 34 个角色按 §3.1 人工核对后并入，其余角色仍需逐角色 curation。
- **产球到达延迟**：gcsim 的粒子默认延迟 100 帧，而内核在下一个动作开始时取消上一个动作尚未到达的事件——
  按 100 帧填会让产球永远被取消，所以 curated 里先按 `travelFrames: 0` 记，作为已知近似。
- **卡肉**：`hitlagFrames` 一律留空，不拿 gcsim 的帧数冒充实测。
- **附着与 ICD**：命中只有直伤与倍率，不带 `reaction`。
- **帧数口径**：包内帧数是 gcsim 的 60fps 口径，内核目前按所选档位的整数帧直接使用，
  跨档位折算尚未实现——在非 `fps-60` 档位跑这批包，动作时长会偏离。
- **旅行者**：七个元素键已进名录，但 gcsim 的旅行者代码在 `traveler/common/<元素>/` 与 `traveler/<元素>/aether|lumine/` 两层，
  当前的目录级抽取拿不到普通攻击帧，未落包。
- **永久数据改为运行时现算**（2026-11-02 用户定）：入库的 `permanent/<charId>-<武器id>-r<精炼>.json` 仍优先读，
  没有这份文件时按玩家实际配装从 miao 现算（`src/model/PermanentSource.ts`，进程内缓存，不写 `data/`）。
  因此换武器/拼队伍不再需要提前跑 `gen-permanent.mjs`；脚本保留给「需要人工审计后再入库」的配装。
  命座效果、4 件套、按类型增伤、抗性、护盾强效一律没有静态建模，只在报告里以「未纳入」披露；
  未登记武器被动按「未审计」披露，不会假装它没有。

### 4.1 4 件套效果（2026-11-02 切片 1/2/3）

**静态通道**：`PermanentStats` 的 `normalDmg / chargedDmg / plungeDmg / skillDmg / burstDmg`
直接加算进伤害公式的 A 乘区，命中类型由动作 id（`*.normal-*` / `*.charged-*` / `*.plunge-*` / `*.skill` / `*.burst`）判定。

**百分比面板通道（切片 3）**：`PanelModifiers` 支持 `atkPct / hpPct / defPct`，按基础面板
（角色白值 + 武器白值）折成点数后再进面板；`hitDamage` 遇到 pct 但上下文缺 `base` 会直接报 issue，
不会静默少算。

**触发通道**：`PermanentData.runtimeEffects` 里的效果带
`trigger: 'cast-skill' | 'cast-burst' | 'skill-hit'`：

- `cast-skill` / `cast-burst`：在该角色起手对应动作的当帧激活（先于本动作命中结算）；
- `skill-hit`：在该角色战技命中当帧激活（本发仍按触发前状态结算）；
- 持续到 `durationFrames`；`teamRun` 只并入本队圣遗物真正穿着的套装（按 `setId` 过滤），没穿的不触发。

## 5. `#队伍伤害` 的取数路径

命令 2026-11-01 起走本内核：前三步读 `data/team-sim/`，永久数据先读入库文件、缺了按玩家配装从 miao 现算；
缺哪一步就说缺哪一步，**不拿 0 或猜测值顶上**：

| 步骤 | 位置 | 缺了怎么说 |
|---|---|---|
| 配装 | miao 公开字段（`TeamBuildAdapter`） | 逐条列出 `artifacts.*`、`talents.*` 的问题 |
| 动作 | `packs/<键>.json`（名录查键） | 「X 还没有 gcsim 动作数据」/「X 不在名录里」 |
| 轴 | `rotations/*.json` | 「本队伍需要轴」+ 文件格式 |
| 永久数据 | `permanent/<charId>-<武器id>-r<精炼>.json` | 「X 缺永久数据（文件名）；同角色已有 …，武器或精炼对不上」 |

### 轴文件

```jsonc
{
  "schemaVersion": 1,
  "id": "geo-four-default",          // 轴身份，进模拟结果
  "team": ["10000030", "10000038", "10000055", "10000057"], // 四人 charId，顺序无关
  "measurementEndFrame": 7243,       // 测量窗口（60 档 = 120 秒）
  "scheduler": "fixed",              // 可选，默认 fixed
  "keymap": {                        // 按键 → 本队动作；版本必须与录制一致
    "version": "geo4-v1",
    "bindings": { "e": { "actorId": "10000030", "actionId": "zhongli.skill" } }
  },
  "recording": {                     // RecordingV1：按键与毫秒时间戳
    "schemaVersion": 1,
    "frameTierId": "fps-60",
    "keymapVersion": "geo4-v1",
    "gameVersion": "7.1",
    "source": "recorded",
    "start": { "activeActorId": "10000030", "actors": [{ "actorId": "10000030", "energy": 0, "energyMax": 40 }] },
    "events": [{ "atMs": 0, "key": "e", "phase": "down" }]

}
```

按 `team` 集合匹配，不看文件名；多份都声明同一队时取文件名排序第一份并在报告里提示。
键位版本不一致、键位指向不存在的动作、窗口小于最后一步帧号，都会被拒绝。

### 永久数据

基础白值与已审计效果，**按「角色 + 武器 + 精炼」一份**，文件名 `<charId>-<武器id>-r<精炼>.json`。
元信息（`gameVersion`/`bundleId`/`source`）必须全部一致，不一致会在面板构建阶段逐条拒绝。

```jsonc
{
  "schemaVersion": 1,
  "gameVersion": "7.1",
  "bundleId": "permanent-7.1",
  "source": "miao meta-gs 7.1（白值/突破/武器副属性）+ 本仓库人工审计（套装与被动）",
  "character": { "id": "10000030", "level": 90, "ascension": 6, "base": { "hp": 14695.09, "atk": 251.14, "def": 737.81 }, "bonuses": [] },
  "weapon": { "id": "13303", "level": 90, "ascension": 6, "baseAtk": 354.38, "bonuses": [] },
  "effects": {
    "character:10000030:a6": { "status": "verified-static", "modifiers": [{ "key": "geo", "value": 0.288 }], "runtimeRequired": false, "unmodeled": "固有天赋条件效果未建模：悬岩宸断、炊金馔玉" },
    "weapon:13303:r1": { "status": "verified-static", "modifiers": [{ "key": "hpPct", "value": 0.4692 }], "runtimeRequired": false },
    "artifact-set:400189:2pc": { "status": "verified-static", "modifiers": [{ "key": "defPct", "value": 0.3 }], "runtimeRequired": false },
    "artifact-set:400189:4pc": { "status": "verified-static", "modifiers": [], "runtimeRequired": true, "unmodeled": "华馆梦醒形骸记 4 件套未建模：…" }

```

生成方式（只读 miao 与名录，不联网）：

```bash
node scripts/gen-permanent.mjs --preset geo-four        # 纯岩四人，写 data/team-sim/permanent/
node scripts/gen-permanent.mjs --preset geo-four --dry  # 写 out/permanent-drafts/，用于抽查
node scripts/gen-permanent.mjs --char 钟离 --weapon 黑缨枪 --refine 1
```

生成器每次同时写入 `out/permanent-report.json`（含生成时间，属于构建产物）——**不放 `data/`**，
保证入库数据可复现。当前入库四份：

| 角色 | charId | 武器 | 武器 id | 效果条数 | 未建模 | 不支持 |
|---|---|---|---|---|---|---|
| 钟离 | 10000030 | 黑缨枪 R1 | 13303 | 130 | 66 | 17 |
| 阿贝多 | 10000038 | 辰砂之纺锤 R1 | 11415 | 130 | 67 | 17 |
| 五郎 | 10000055 | 西风猎弓 R1 | 15401 | 130 | 67 | 17 |
| 荒泷一斗 | 10000057 | 赤角石溃杵 R1 | 12510 | 130 | 67 | 17 |

130 条 = 63 套 × 2pc + 63 套 × 4pc + 角色突破 + 武器 + 命座 1–6（多出来的条目当前配装用不到，
重新配装时不必再跑生成器）。效果只有三态：

- `verified-static`：静态部分已算进面板。
- `known-no-static`：确认没有静态加成，必须是空 `modifiers`。
- `unsupported`：整套不支持（如抗性、护盾强效、受治疗、夜魂、按类型增伤），**运行期会整轮失败**。

条件效果（4 件套、命座、武器被动里的条件部分）不阻塞面板，而是走 `unmodeled` 分层：
面板照算静态部分 → 结算结果带 `unmodeled` → 报告固定输出「未纳入：…，以下数字偏低估」→
发布闸门 `accuracy` 关据此判 `blocked`。这是 2026-11-01 定下的口径：既不让命令因为一条
4 件套直接罢工，也不让数字假装已经完整。

每人一份数据只覆盖一套武器；换武器需要重新生成一份（或改 `--weapon`），缺的那份点名报错。
