# 功能与命令

> 本册是**命令全集与触发口径**的唯一维护处。命令文案、正则、优先级的**代码来源**是
> `src/components/constants.ts`（改命令必须同批改本册）与各 `src/apps/*.ts`。

## 帮助入口（两小一大）

| 入口 | 页面内容 | 规则 |
|---|---|---|
| `#meta` / `#Meta帮助` | 总帮助 | `META_HELP_RULE` `/^#?(?:meta\|Meta\|META)(?:帮助\|说明)?$/` |
| `#攻略帮助`（= `#攻略` / `#攻略说明`） | 攻略 + 练度 | `HELP_RULE` `/^#?攻略(?:说明\|帮助)?$/` |
| `#DPS帮助` | 伤害 + 榜单 + 状态 | `RULES.help` |

三者由同一个 handler（`src/apps/help.ts` 的 `MetaHelp.handleHelp`）出图，**渲染失败回落同源文本**。

## 攻略入口（后缀式）

| 命令 | 规则 |
|---|---|
| `#胡桃攻略` / `#胡桃攻略2` / `#胡桃指南` | `CODEX_SUFFIX_RULE` `/^#?(更新)?(?!.*设置默认攻略)([^#\s]\S*?)攻略([1-7])?$/` |
| `#攻略列表` / `#攻略状态` | `CODEX_META_RULE` `/^#攻略(列表\|状态)$/` |

- 三个全局词 `#攻略` / `#攻略帮助` / `#攻略说明` 由帮助 app 认领（`accept()` 只认领它们与 `#meta`）。
- **负向断言 `(?!.*设置默认攻略)` 必须保留**：`#设置默认攻略3` 也以「攻略3」结尾，否则会被吞掉。
- `CODEX_GUIDE_RULE`（`^#(.+)指南$`）与 `CODEX_ARG_RULE`（`^#攻略\s+(.+)$`）**入口已移除**，只留给 `src/modules/branches.ts` 的解析器使用；**不得加回命令入口**。

### 命名冲突侦察（为什么这么定）

| 占用方 | 已占用的词 | 我们的规避 |
|---|---|---|
| **miao-plugin**（`challenge.js`，**priority 1**，永远先跑） | `#危战`、`#危战数据`、`#危战排名`、`#危战单人`、`#幽境危战` | 危战规则**必带档位**（`n6\|n7`）：裸形态一个都不认领；只留 `raidTiersPrompt` 兜"写了筛选忘档位" |
| miao-plugin（`profile.js`） | `#练度统计`、`#xx排名/排行/最强`、`#群xx排名榜` | 用 `#练度查询` / `#练度榜`（不同词）；`#DPS榜` 不含"排名/排行" |
| miao-plugin（`stat.js`） | `#深渊/幽境/危战 出场率` | 同上（必带档位） |
| genshin（`strategy.js`，priority 50） | `#xx攻略`、`#攻略说明/帮助`、`#设置默认攻略N` | 既有设计：攻略抢占 `-100000`，`(?!.*设置默认攻略)` 负向断言保留 |
| system / Atlas / miao | `#状态`、`#统计`、`#图鉴状态`、`#签到状态` | 插件自身命令带 `#meta` 命名空间 → `#meta状态` |

> 实测 0 占用的新名：`#练度榜`、`#榜视频`、`#危战视频`、`#meta状态`、`#榜单刷新`、`#配装`、`#队伍伤害`。

## 路由优先级与放行边界

| 处理者 | priority | 说明 |
|---|---|---|
| 本插件 · 攻略 / 帮助 | **-100000**（`PREEMPT_PRIORITY`，写死不可配置） | 早于 Atlas 快捷入口（-99999）与 `plugins/genshin`「米游社攻略」（50） |

## 模块开关（功能层）

13 个模块各一个开关——已随 2026-10-15 命令面重构收敛为 **11 个**（配置键 `modules.<键>`，**默认全开**；**`teamDamage` 默认关闭**）。锅巴面板里是「模块开关」分组。

| 键 | 模块 | 覆盖命令 |
|---|---|---|
| `codex` | 角色攻略 | `#胡桃攻略` / `#胡桃攻略2` / `#胡桃指南` |
| `help` | 帮助页 | `#meta` / `#攻略帮助` / `#攻略说明` / `#攻略` / `#DPS帮助` |
| `rank` | DPS 榜（含角色档位视图） | `#DPS榜 …` / `#DPS …`（带角色名 = 按金档分层） |
| `raidTiers` | 危战分档 | `#危战 … n6\|n7`（**须指定档位**；不写则提示选档） |
| `build` | 练度榜 | `#练度榜 [角色] [UID]` |
| `grade` | 练度提升指南 | `#练度查询 胡桃` |
| `akashaBuild` | 榜上配装 | `#配装 胡桃 [名次]` |
| `teamDamage` | 队伍伤害（**默认关闭**） | `#队伍伤害<N> A B C D [词条…]`（N = 配置 `teamDamageAxes` 的序号轴，省略 = 1） |
| `video` | 榜单视频 | `#视频 <名次>` / `#危战视频 <名次>` |
| `status` | 状态页 | `#meta状态` |
| `admin` | 数据管理 | `#榜单刷新` / `#榜单刷新` / `#榜单刷新`（仅主人） |

**关闭后的行为**（用户 2026-10-15 定）：

- **非接管类**（其余 11 个模块）：回一条 `「<模块名>」已在配置中关闭（modules.<键>）…`，消息由本插件消费（命名空间稳定）。
- **接管类**（`codex` / `help`）：本插件**不认领**（`accept` 返回 false）且 handler 返回 `false` 放行 → `#胡桃攻略` 落回 `plugins/genshin`「米游社攻略」/ Atlas，不会出现"占着坑却不干活"。

**三层开关正交，不得互相替代**（见 `AGENTS.md` 硬约束 8/12）：

| 层 | 键 | 管什么 |
|---|---|---|
| 功能层 | `modules.*` | 模块的命令是否响应 |
| 查询联网层 | `networkEnabled` | 业务查询是否允许远程访问/刷新（**只**管辖查询类，不是全局联网禁令） |
| 数据通道层 | `akashaEnabled` | 是否允许走阿卡莎通道（浏览器会话） |

锅巴面板里的分组与之对应：**「模块开关（功能层）」→「业务查询联网（查询联网层）」→「数据源二 · akasha.cv（数据通道层）」**；`defSet/config.yaml` 的注释是同一口径（改文案时两边一起改）。

## 练度评分口径（`#练度查询`，2026-10-15 用户定）

- **三维加权**（`gradeWeights`，默认 `comprehensive:65,weapon:20,talent:15`）：
  `综合`（**圣遗物有效词条**为主 = miao 评分档位 ×0.8 + 套装符合度 ×0.2）/ `武器`（是否在推荐档）/ `天赋`（目标等级）。
- **面板与圣遗物已合并**：面板数值本来就是武器与圣遗物词条的产物，分两维等于把同一件事算两次。
- **面板目标不计分、不设严格限制**：攻略里的面板区间只在对比表的「参考」组展示（`verdict: info`），
  不进总分、也不进"未达标项"。
- **毕业档**（大毕业 / 毕业 / 小毕业）按**综合（词条）分**判定；等级不足时最高「小毕业」。
- **圣遗物评分走 miao 的评分规则**（`ArtisMark.getMarkDetail()`：有效词条加权分 + `MAX…D` 档位），页面脚注口径行写明。
- 旧配置兼容：`gradeWeights` 里写 `panel` + `artifact` 会自动相加折进 `comprehensive`（见 `getGradeWeights()`）。

**页面结构（2026-10-15 用户定）**：**立绘行（完全 miao 同款：左立绘 + 右实际面板）** → 结论（档位 + 三维条）→ **当前配装**（武器 → 圣遗物套装 + miao 评分与有效词条数 → 天赋加点，**不列单件圣遗物、不列伤害、不单列等级行**）→ 未达标项 → 提升建议 → **参考 DPS** → 脚注。

**页面宽度（2026-10-15 用户定）**：练度页整页 **600px**（照抄 miao 面板的 `body { width: 600px }`），立绘行因此能用 miao 的原值（1400×500 / `margin-left:-545px`）而无需换算；**立绘行以下的分区随 600px 自适应**。

- **立绘行（逐条照抄 miao，只加 `gd-` 前缀，数值一个不改）**：`.gd-basic`（miao `.basic`）→ `.gd-main-pic`（`.main-pic`：1400×500、`contain`+`center`、`margin-left:-545px`）→ `.gd-detail`（`.detail`：`absolute; right:20px; top:20px`，内含 `.gd-char-name`(50px) / `.gd-char-lv` / `.gd-char-talents` / `.gd-char-attr`）→ `.gd-char-cons`（`.char-cons`：`flex; width:250px; absolute; bottom:5px; left:20px`）。
- **立绘图**：优先 miao 的 `meta-gs/character/{角色}/imgs/{costumeSplash,splash}.webp`（miao 的 `costumeSplash || imgs?.splash`），缺图回落到 ProfileImg 图库图。
- **面板 = `.char-attr`**：`li` 固定 **300×32px**、斑马行（odd `rgba(50,50,50,.4)` / even `rgba(0,0,0,.4)`）、**五列**（照抄 miao `profile-detail.html:50-67`）：`.icon`(26px，精灵图 `resources/character/imgs/icon.png` + `.i-hp/-16px … .i-dmg/-128px`) / `.title`(75px) / `.weight`(36px，属性权重小方块 `cw[key]`，`>= 80` 金色 `#ffe699`) / `.value`(100px 右对齐) / `.value2`(70px，白字基础值 + 绿字 `+加成`，`0.0%` 走 `.zero` 灰)；**只有属性名与数值**（不加目标、不加达标条）。
- **面板数值文本走 miao 自己的格式化**（照抄 `apps/profile/ProfileDetail.js:216-242`）：直接调 miao 的 `Format.comma`（`hp` 取整 + 万位分组、其余 1 位小数）与 `Format.pct`（1 位小数 + `%`，`phy > dmg` 时 `dmg` 行显示物理伤害），并把 `{key}Base` / `{key}Plus` 一并算出来给第五列 —— 不自己实现一份，否则小数点位数/千分位分组会和面板对不上（曾显示成 `47268.265412357367`）。
- **面板属性权重**：取 miao **带明细**的 `getArtisMark(true).charWeight`（`ArtisMark.getMarkDetail` 只在 `withDetail` 时给这个字段；`getArtisDetail()` 里没有），与「有效词条数」的过滤同源。
- **天赋行 = `.char-talents`**：顺序 a/e/q，图标**照抄 miao `CharImg.getImgs()` 的逻辑**——`talentCons[key] > 0` 时用**该命座的图标** `icons/cons-N.webp`，否则用 `icons/talent-{key}.webp`（`talentCons` 读 miao 的 `data.json`）；被命座加成（`level > original`）加 `talent-plus`（深底金字），`original >= 10` 加 `talent-crown`（皇冠 `resources/character/imgs/crown.png`，`top:0` 贴着圆环顶边）。
- **图标圆环**：`<body>` 上挂 `gd-elem-{elem}`（元素取自 miao `char.elem`，中文元素名按 miao `elem.html:15` 的表翻译），CSS 照抄 miao `common/common.css:208-266` 给 `.gd-talent-icon` 铺 `common/bg/talent-{elem}.webp`；`.gd-talent-icon` 必须带 **`z-index: 90`**（miao `profile-detail.css:226`），否则左下角命座行会被 `z-index: 2` 的立绘盖住（表现为"命座图标消失"）。
- **命座徽章**：照抄 miao —— `.char-lv .cons`（`profile-detail.css`：`margin-left:5px; vertical-align:bottom`）+ `.cons` / `.cons-N`（`common/css/common.css`：`padding:0 5px; border-radius:4px`，底色按命座数 0=`#666` / 1=`#5cbac2` / 2=`#339d61` / 3=`#3e95b9` / 4=`#3955b7` / 5=`#531ba9cf` / 6=`#ff5722`，均白字）。
- **命座行 = `.char-cons`**：`.talent-icon` 50×50、`margin:0 -5px`，未解锁 `.off { filter: grayscale(100%); opacity: .4 }`，图标 `icons/cons-N.webp`；条目是 `.cons-item`（**不参与 flex 均分**，宽度由 50px 图标 − 左右各 5px 外边距得来）。

- **圣遗物套装表述**：只写 **4 件套**（`X×4`）/ **2+2**（`X×2 + Y×2`）/ **2 件套**（`X×2`）；凑不出套装加成就写「散件」——**不列单件散件**。
- **评分与词条**：右侧先给 miao 圣遗物评分（`评分 246.4 ACE`），再给**有效词条数**——取 miao 评分明细里 `charWeight[key] > 0` 的那些 `attrs[].eff` 之和（**无效词条不计**，与 miao 面板口径一致），显示为 `词条数：42.4`；**不是**数副词条条目数（那是每件 4 条 = 20，与 miao 对不上）。
- **参考 DPS**：以**当前金数**（该角色自身投入 = 角色 1 金 + 命座 + 5★ 武器 1 金）为基底、**向下取 4 的倍数**、步长 4、最多 3 档（例：C1 + 5★ = 3 → 基底 4 → 4 / 8 / 12 金），每档取**含该角色**的最高伤害记录；榜单缓存不可用时不出这一块。
- **角色立绘**：`src/model/ProfileImgRes.ts` 按图库插件 **ProfileImg-Plugin** 的目录约定取图 ——
  源列表读 miao `config/profile.js` 的 `profileImgSrc`（`['profile', 各仓库绝对路径…]`），
  每个源下按 `normal-character/{角色}/`、`super-character/{角色}/`、平铺 `{角色}/` 找图，只认 `webp/png/jpg/jpeg`（`.bak` 屏蔽）；
  命中后复制进 `out/profileimg/`（未跟踪缓存）供模板引用。**顺序：ProfileImg 图库 → miao 默认图库 → 不显示**，全程降级不报错。
- **脚注**：只保留**一行口径 + 版权**（合计 ≤2 行）；面板/命座等已被页面可视化的细节不再重复写。
- **档位配色**：与 miao 同款（取自 `miao-plugin/.../profile-detail.css` 的 `mark-*` 表）——**MAX / ACE 红 `#e85656`**、SSS / SS 金 `#ffe699`、S / A 紫 `#d699ff`、B 及以下默认文字色；综合档位与圣遗物评分档位都按此上色，**未达标项也用同一红色**。
- **行内不换行**：圣遗物行右侧（`评分 246.4 ACE　词条数：45.3`）占固定宽度、`white-space: nowrap`，避免长文本折行导致与左侧套装名错位。

## 账号与隐私口径

- **凡涉及"我的账号"的命令都不带 UID**：`#练度查询` 只接一个角色名，账号走 miao 的米游社绑定（用户 `#扫码登录` 一次）。
  `#练度查询 胡桃 100000000` 这类 UID 形态属**遗留写法**，2026-10-15 起不再支持：app 会回一句改用提示并指向 `#练度榜`。
- 例外：`#练度榜 [角色] [UID]`（阿卡莎名次面板）与 `#队伍伤害 … [UID]` 仍可显式写 UID。
- 米游社 ck 由 miao 保存；本插件不保存凭据，状态页只回显"是否配置代理"与"已关闭的模块"。
