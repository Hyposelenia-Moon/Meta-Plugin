# 功能与命令

> 本册是**命令全集与触发口径**的唯一维护处。命令文案、正则、优先级的**代码来源**是
> `src/components/constants.ts`（改命令必须同批改本册）与各 `src/apps/*.ts`。

## 帮助入口（两小一大）

| 入口 | 页面内容 | 规则 |
|---|---|---|
| `#meta` / `#Meta帮助` | 总帮助 | `META_HELP_RULE` `/^#?(?:meta\|Meta\|META)(?:帮助\|说明)?$/` |
| `#攻略帮助`（= `#攻略` / `#攻略说明`） | 攻略 + 练度 | `HELP_RULE` `/^#?攻略(?:说明\|帮助)?$/` |
| `#DPS帮助` | 伤害 + 榜单 + 状态 | `RULES.help` |

三者由同一个 handler（`src/apps/help.ts` 的 `MetaHelp.handleHelp`）出图，**渲染失败回落同源文本**。

## 攻略入口（后缀式）

| 命令 | 规则 |
|---|---|
| `#胡桃攻略` / `#胡桃攻略2` / `#胡桃指南` | `CODEX_SUFFIX_RULE` `/^#?(更新)?(?!.*设置默认攻略)([^#\s]\S*?)攻略([1-7])?(?:\s*面板图([1-9]\d*))?$/` |
| `#胡桃攻略 面板图3` | 同上（`面板图N` 指定图库里的第 N 张立绘；带不带空格都认） |
| `#攻略列表` / `#攻略状态` | `CODEX_META_RULE` `/^#攻略(列表\|状态)$/` |

- 三个全局词 `#攻略` / `#攻略帮助` / `#攻略说明` 由帮助 app 认领（`accept()` 只认领它们与 `#meta`）。
- **负向断言 `(?!.*设置默认攻略)` 必须保留**：`#设置默认攻略3` 也以「攻略3」结尾，否则会被吞掉。
- **`面板图N`（2026-10-17 加）**：`#胡桃攻略 面板图3` 让攻略页立绘改用图库 `{角色}_{序号}_…` 的第 3 张（与 `#练度查询 胡桃 面板图3` 同口径）。点名要哪张就照用，不再卡「不小于默认立绘」；白边仍按离线清单裁剪 + 模糊层铺满。序号在图库里不存在时退回随机取图，原因写在 `pickPagePortrait().note` 里。
- `CODEX_GUIDE_RULE`（`^#(.+)指南$`）与 `CODEX_ARG_RULE`（`^#攻略\s+(.+)$`）**入口已移除**，只留给 `src/modules/branches.ts` 的解析器使用；**不得加回命令入口**。

  **显式** `标签:X` 原样参与筛选，匹配不到就如实给 0 命中并在摘要里写明标签。
- **0 命中不出空图**（2026-10-15 用户反馈）：一条都没命中时 `modules/respond.ts` 直接走文本回退、不渲染，
  文本里带上筛选条件与命中数（`rankQuery.filterSummary()`；角色档位页副标题同样带上）—— 空图看不出"是哪个筛选把结果筛没了"。
- 危战单档一页 **10 条**（`DEFAULT_TIER_ROWS`，2026-10-15 用户定：由 5 提到 10）。
- 危战页页头**只有标题 + 元信息（命中条数 / 数据时间）**，不渲染副标题行（2026-10-15 用户定）—— 首领与版本本来就在每行标签里、命中数在元信息里，那行长文本属重复；`result.subtitle` 仍留给文本回退与「请选档」提示用。
- `#DPS榜 <角色>`（角色档位视图）按 **每 4 金一档**（`COST_STEP = 4`：`≤ 4 金` / `5-8 金` / `9-12 金` …，2026-10-15 用户定），**每档最多 4 条**（`DEFAULT_PER_TIER = 4`，该档记录不足就少列）；档位过多时仍只留记录最多的 8 档并如实说明丢弃几档。

**关闭后的行为**（用户 2026-10-15 定）：

- **非接管类**（其余 7 个模块）：回一条 `「<模块名>」已在配置中关闭（modules.<键>）…`，消息由本插件消费（命名空间稳定）。

## 练度评分口径（`#练度查询`，2026-10-15 用户定）

- **三维加权**（`gradeWeights`，默认 `comprehensive:65,weapon:20,talent:15`）：
  `综合`（**圣遗物有效词条**为主 = miao 评分档位 ×0.8 + 套装符合度 ×0.2）/ `武器`（是否在推荐档）/ `天赋`（目标等级）。
- **面板与圣遗物已合并**：面板数值本来就是武器与圣遗物词条的产物，分两维等于把同一件事算两次。
- **面板目标不计分、不设严格限制**：攻略里的面板区间只在对比表的「参考」组展示（`verdict: info`），
  不进总分、也不进"未达标项"。
- **毕业档**（大毕业 / 毕业 / 小毕业）按**综合（词条）分**判定；等级不足时最高「小毕业」。
- **圣遗物评分走 miao 的评分规则**（`ArtisMark.getMarkDetail()`：有效词条加权分 + `MAX…D` 档位），页面脚注口径行写明。

**页面结构（2026-10-15 用户定）**：**立绘行（完全 miao 同款：左立绘 + 右实际面板）** → 结论（档位 + 三维条）→ **当前配装**（武器 → 圣遗物套装 + miao 评分与有效词条数 → 天赋加点，**不列单件圣遗物、不列伤害、不单列等级行**）→ 未达标项 → 提升建议 → **参考 DPS** → 脚注。

**页面宽度（2026-10-15 用户定）**：练度页整页 **600px**（照抄 miao 面板的 `body { width: 600px }`），立绘行因此能用 miao 的原值（1400×500 / `margin-left:-545px`）而无需换算；**立绘行以下的分区随 600px 自适应**。

## 攻略页立绘口径（`#胡桃攻略` 的立绘区，2026-10-17 用户定稿）

结构：**一张圆角图，铺满卡片，无内框**。`.codex-portrait`（`aspect-ratio` = 默认立绘宽高比定高、四角 20px 圆角、`overflow:hidden` 裁圆）→ `.codex-portrait-img`（唯一图层：inline 定位，`planPortraitBox(..., 'cover')`；白边已裁、cover 铺满并居中）。
**不要**再往立绘外面套图层 —— 模糊底（`.codex-portrait-bg`）与边缘描边（`.codex-portrait-edge`）都已删除：它们会造成「卡片套卡片」的观感（用户 2026-10-17 反馈），而 cover 已经铺满、没有空缺需要填。**页头卡片（`Meta-Plugin · 角色攻略`）也已整块移除**，页面直接从立绘卡开始。

- **取图顺序**：图库（普通层 `profileImgPool`）→ miao 自带立绘（`splash.webp`）→ 不画。攻略页与账号无关，**不碰 `super-character` 彩蛋层**。
- **唯一的筛选条件（2026-10-17 改版）：按「卡片真实渲染尺寸」算放大倍数** —— 不再拿 miao 默认立绘当基准。卡片 = 780 CSS 宽 × enderScale（默认 1.5）→ **1170px** 宽，高 = 宽 ÷ 卡片比例；把「裁掉白边后的那块」按 cover 铺进卡片，**放大倍数 > 1.15 才排除**（面积过小会发虚）。实测：117 个有图库的角色里 **106 个**能用图库图（旧口径只有 93 个）；itsRenderSize() 的容差可调。
- **留白裁剪（2026-10-17 定稿，不依赖本机扫描）**：图库里有些图**画布被挪过、四周留了一条纯色带**（全量 746 张里 234 张命中，白色为主，另有 AI 扩图留下的近白/带色窄边）。四边比例来自两级清单：**① 入库基线** `data/_portrait-padding.json`（键=文件名，仓库自带，任何副本装好就能裁）→ **② 本机清单** `out/portrait-padding.json`（未跟踪，`node scripts/scan-portrait-padding.mjs --baseline` 重扫，按绝对路径命中并覆盖基线）。运行时按比例把留白推出取景窗外（主体层放大并位移），剩下的边由边缘模糊线过渡。
- **扫描判据（`scripts/scan-portrait-padding.mjs`）**：① 一条线（整列/整行）里 ≥98% 采样点与该线均值偏差 ≤6 → 纯色线；或 ≥95% 像素纯白 → 白线（兼容渐变白边）；② 从边向内连续同色形成 ≥3% 的带才算；③ 护栏：**纯白**留白宽度不限，**非白**留白只允许 ≤12% —— 否则黑底画作（如「黑底月亮」彩蛋图）的整块底色会被误当留白裁掉。重扫时与已有基线**按边取大合并**（不覆盖变小），避免判定口径演进导致白边复发。
- **页面内「自量自裁」（2026-10-17 第四轮，用户定）**：清单按**文件名**索引，图库不同步/换图时那张图不在清单里就会漏裁（实测某机瓦雷莎左侧 19.7% 纯白没被裁）。所以立绘改用 **`data:` URL 内嵌**（同源，canvas 不被污染），模板末尾的内联脚本用**与扫描器同一套判据**（参数来自 `ProfileImgRes.cropCfg`，唯一来源）量四边，再用**与 `planPortraitBox()` 同一套 cover 数学**摆正并**居中**；服务端盒只作首帧兜底，脚本跑完即覆盖。取像素失败（图被污染等）→ 直接 return，保持服务端盒。端到端自检：`node scripts/portrait-autocrop-selftest.mjs`（造一张 20% 左白图，断言页面盒与 `planPortraitBox` 一致且盖满取景窗）。
- **立绘区字号与配色（2026-10-17）**：文字块压一层「右浓左透」黑底提对比；名字用装饰字体栈 + 金色 `#ffe6b3` + 多层黑阴影 + 名下金色分隔细线，**字重 400**（装饰字体本身够重，再用 700 会合成粗体、边缘发糊）。**层级只在一处定义**：名字 42px / 副标题胶囊 19px + **700 粗体** / 定位 19px / meta（建议等级、100级提升）19px —— 副标题是「标签」不是第二主标题，所以缩小并加粗；历史上散布的 24/26/28/30px 覆盖已全部删除（它们互相打架、最终生效果的是 28px，才导致「区域大小失衡 + chip 突兀」）。
- **面板区网格排版（2026-10-17）**：`section.kind === 'stats'` 时按 `属性：数值` 逐格渲染。用**等宽列网格**（`display: grid` + `repeat(auto-fit, minmax(300px, 1fr))`，列间距 28px）：列宽相等 → 独占一行的格子（如「生命值」）其数值右缘与**上行同列**数值对齐，不会飘到卡片最右；**字号与其它区一致**（标签 22px = 行标签、数值 26px = 正文）。**格子不画独立底板**（无背景/无左侧色条，只用一条下划线分栏），否则整块会显得「缩在卡片里」；左右边界与其它行严格对齐（同为 `--mx-inset` 内缩）。
- **正文标签语义配色（2026-10-17）**：`presentation.labelToneOf()` 把行标签分四档 —— 核心（推荐/主词条/命之座/月结晶…）金、备选（可选/副词条/次选/替代）蓝、过程（过渡/其他/通用/输出向/辅助向）灰、未识别正文色；模板输出 `tone-*` 类，便于扫读定位。
- **标题区「角色攻略」用原神字体（2026-10-17 用户定）**：字体 = 汉仪文黑-65W（miao / 面板图同款，仓库自带 `resources/common/font/HYWH-65W.woff`）。由 `model/genshinFont.ts` 解析文件并给出**编码后的 `file://` URL** + 独立族名 `CodexGenshin`，模板注入 `@font-face` 并写进 `--codex-title-font`，`.codex-name-sub` 用 `var(--codex-title-font, 系统中文无衬)`。
  ⚠ **不要**复用模板里那个 `YS`：它用 `{{_miao_path}}` 拼 URL（路径带空格未编码）→ 浏览器报 `ERR_FILE_NOT_FOUND`、字体静默回落系统字体（实测 `document.fonts.check('20px YS')` = false）。找不到字体文件时整段不注入，自动回落系统字体。
- **副词条分隔符间距（2026-10-17 用户定）**：`＞` 两侧原来 ≈33px（12px 外边距 + 3px 内边距 + 副词条自己的 18px column-gap）→ 文字行改紧凑：分隔符外边距 1px、副词条 `column-gap` 18px → 6px，两侧各约 7px；宽间距只保留给**带图标**的条目（`.codex-item:has(.codex-icon) > .codex-sep`）。
- **页脚两行（2026-10-17 用户定）**：第一行 = `最后更新时间：YYYY.MM.DD · 面板与命座数值仅供参考`，第二行 = 版权。**不再出现「本仓库攻略数据」「本地数据」**；时间取**攻略数据文件的实际 mtime**（`CodexStore.guideMtime()` → `YYYY.MM.DD`，数据一改就变；读不到写「未提供」）。
- **配队头像间距**：+ 用**显式固定值**（.codex-team .codex-sep { margin: 0 10px; font-size: 24px }）；正文行的紧凑规则收窄为 .codex-row .codex-sep { margin: 0 1px }，两条互不影响（2026-10-17 用户反馈头像间距曾被行内规则带跑）。
- **比例不卡**：1920×1080 这类大图照样用 —— 主体层按「裁留白后的整块 **cover 放大到铺满**」摆进取景窗（最长边先满、溢出的部分裁掉）并**居中**，所以卡片永远没有空缺，**版面高度始终等于默认立绘的比例**。
