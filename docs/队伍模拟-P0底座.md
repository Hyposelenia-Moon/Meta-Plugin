# 队伍模拟 P0：原始配装与普通直伤底座

## 状态与范围

P0 是独立调用的内部 API，没有接管 `#队伍伤害`、旧序号轴、榜单、练度评分或页面。旧命令仍调用原来的聚合行估算；未新增配置与用户命令。

已实现：

- 从 miao Avatar/Artis 公开字段读取角色、武器、原始天赋和五件圣遗物。
- 严格字段/单位/完整性校验；缺少原始字段不从最终面板反推，也不补默认装备值。
- 通过显式基础数据和已审计静态效果构建永久面板。
- 普通、无反应、单次直伤的基础伤害、增伤、暴击、防御、抗性乘区，以及可追溯的 factors。
- 四套离线回归；四个独立角色的永久面板与四种构筑形状均为合成夹具，不是真实账号或游戏实测。
- 旧关键词轴聚合只能产出显式标记的 `legacy-estimate`，不能冒充新引擎结果。

未实现：动作库与倍率数据包、伤害时间线、组队增益、快照、触发与召唤、附着/ICD、所有元素反应、能量/体力、轴可行性和多轴对比。天赋等级加成只有能指认来源时才登记（`talents.modifiers`），P0 不据此推算伤害；`bundleId` 只核对标识、不校验数据内容；只有最终面板的输入被明确拒绝；机制覆盖与误差界（`Coverage` / `errorBound`）在 P1 随动作与机制 fixture 引入，P0 不提供误差结论。所有 P0 配装与永久面板输出均明确 `simulationReady:false`，不得宣传为整队打桩模拟。

**没有已验收的游戏版本全量数据包，没有 B 站黄金实测案例，没有打桩误差或性能达标结论。** 文档中的游戏版本字符串是调用上下文，不构成版本机制覆盖证明。

## 分层与 API

| 文件 | API / 职责 |
|---|---|
| `src/modules/teamSimulation/types.ts` | 单位、配装、机制来源、结果与失败契约；`legacyEstimate(...)` 构造显式旧口径结果 |
| `src/model/TeamBuildAdapter.ts` | `adaptMiaoAvatar(input, provenance)`：纯公开字段适配；`readTeamBuilds(event,names,uid?)`：只读四人缓存编排 |
| `src/modules/teamSimulation/build.ts` | `validateCharacterBuild(input)`、`requiredEffectSources(build)`、`buildPermanentStats(build,data,expected)` |
| `src/modules/teamSimulation/formula.ts` | `calculateOrdinaryHit(input)`：普通无反应单 hit；`TARGET_PRESETS` 只读测试目标口径 |

目录以实现为准：`src/modules/teamSimulation/` + `src/model/TeamBuildAdapter.ts`；探索方案 §4 拟议的 `src/components/team-sim/` 未采纳，避免与现有 `src/components/` 的渲染组件混放。

源码统一由 TypeScript 编译到入库 `lib/`，不可手工修改编译产物。

### 适配器输入

只读取 miao 的 `id/char/elem/level/promote/cons/weapon/talent/artis`。

- 角色突破读取 `promote`，不按等级猜测。
- 原始天赋读取 `talent.a/e/q.original`，不使用命座加成后的 `level` 代替。`talents.modifiers` 只在能指认来源（且该来源已登记为 requiredEffect）时登记；无法指认就省略，等于“未建模”，不凭 `level - original` 猜来源。
- 只有最终面板、说不清哪些效果已计入的输入（`panelCheck`）在 P0 明确拒绝为 unsupported：不能先假定“未含”再把效果加一遍。
- 武器读取实际 id、level、promote、affix，缺精炼或突破即报告；精炼与突破同时写进效果来源 id（见「永久面板」的来源格式），不靠 id 裸奔套用。
- 圣遗物使用公开 `avatar.artis.forEach()`，索引 1..5 对应花/羽/沙/杯/冠；不使用套装摘要或格式化后的 `getArtisDetail()` 数值。
- 主词条要求解码 id 与 mainId 一致，且主词条类型必须落在该部位允许的集合内（花/羽只有固定生命/攻击，沙/杯/冠按游戏允许的主词条）；副词条要求 `upNum` 合计等于原始 `attrIds.length`，不接受静默跳过未知 id 的半解码结果。五星满级圣遗物在游戏内恒为 4 条副词条，空副词条或不足 4 条一律拒绝；`attrIds` 记录的是每次强化（同一词条多次强化会合并成一条 `attrs`），条数只能按 `attrs.length` 判。
- 百分数只在适配入口除以 100：miao `atk/hp/def` 词条是百分数，转换为 `atkPct/hpPct/defPct`；`atkPlus/hpPlus/defPlus` 是固定值，转换为 `atk/hp/def`。暴击、充能、各元素增伤同样转为比例；精通保持点数。
- 不读取 `avatar.attr`，不调用 `calcDmg()`；不刷新面板，不改写 `Player.e`。
- 来源时间保留源值，未知明确 null，不用当前时间伪造面板更新时间。miao 版本暂为 null，不声称完成运行版本指纹。
- 本地四人读取使用一个 Player，`getAvatar(id,false)` 不创建缺失面板；四人重复角色拒绝。

契约层（`validateCharacterBuild`）不依赖适配器，独立复核主词条部位、副词条重复键与主副同键：适配器不是唯一防线，手写或搬运的输入直接调 `buildPermanentStats` 也绕不过去。

来源结构已对照本机 miao 的 `models/Avatar.js`、`models/artis/Artis.js`、`models/artis/ArtisAttr.js`、`resources/meta-gs/artifact/extra.js`。第三方文件只读，未作修改。测试夹具只复现结构，不复制真实账号数据。

## 永久面板

`buildPermanentStats(build,data,expected)` 要求调用方显式提供 `expected.gameVersion/bundleId/source`，与基础数据三项核对；角色和武器的身份、等级、突破必须与原始配装一致。精炼不在 `PermanentData.weapon` 的字段里，改由效果来源 id 的 `:r<精炼>` 体现：审计表登记的是哪个档位就只能用哪个档位。基础白值必须来自维护者提供的版本化数据，不能从最终面板反推。

基础常驻值仅合成一次：暴击率 0.05、暴伤 0.5、充能 1。加上明确审计过的静态效果与圣遗物主副词条后：

```text
HP  = 角色基础HP × (1 + HP%) + 固定HP
ATK = (角色基础ATK + 武器基础ATK) × (1 + ATK%) + 固定ATK
DEF = 角色基础DEF × (1 + DEF%) + 固定DEF
```

所有机制来源必须显式登记并审计，不能通过清空 `requiredEffects` 绕过：

```text
character:<角色id>:a<角色突破>
weapon:<武器id>:r<武器精炼>
constellation:<角色id>:<当前命座>      # 当前命座大于0
artifact-set:<套装id>:2pc             # 至少2件
artifact-set:<套装id>:4pc             # 至少4件
```

角色与武器必须带真实档位：同一角色的不同突破、同一武器的不同精炼，静态效果可能不同，只写 id 会让低档位的 `verified-static` 静默套到高档位上。审计表按档位逐条登记，数据只覆盖另一档位时报缺来源，而不是猜。

`PermanentData.character.bonuses` 与 `weapon.bonuses` 保留字段但**必须是空数组**：静态加成只能登记到对应来源效果的 `modifiers`，非空即按 unsupported 拒绝。突破加成登记在 `character:<id>:a<突破>` 的名下，武器效果登记在 `weapon:<id>:r<精炼>` 的名下，这样每一分属性都能追到一条已审计来源，而不是走一条谁都能塞的自由通道。

每项效果标为 `verified-static`、`known-no-static` 或 `unsupported`；缺来源、缺效果或 unsupported 拒绝面板构建。`runtimeRequired` 效果单列进 `runtimeEffects`，P0 不执行；某命座记录代表该命座及以前全部适用效果的维护者审计，不是仅登记最后一级就等于完整支持。

返回白值、面板、套装件数、机制审计和逐项属性 trace；即便永久面板就绪，也不代表动作/伤害机制已经就绪。

`bundleId` 只用于核对“是不是同一份数据包”，不校验数据内容是否被替换；版本化数据的哈希或签名要等数据包落地后再补，不能把三项元信息一致当成防篡改。

## 普通无反应直伤

调用必须显式提供 `kind:'ordinary'`、`reaction:'none'`、版本、来源以及每个乘区。未知伤害类型或反应直接 unsupported。公式只接收已明确适用的普通直伤输入，不接受“把所有反应都乘进去”。

```text
B = Σ(属性点数 × 天赋倍率) + 附加基础伤害
C = 1                                      # 不暴击或不能暴击
C = 1 + CD                                 # 固定暴击
C = 1 + clamp(CR,0,1) × CD                  # 不影响后续状态的期望暴击
Fdef = (角色等级+100) / [(角色等级+100)+(敌等级+100)×(1-减防)×(1-无视防御)]
r = 敌抗 - 减抗
Fres = 1-r/2       (r<0)
     = 1-r         (0≤r<0.75)
     = 1/(1+4r)    (r≥0.75)
D = B × (1+适用增伤) × C × Fdef × Fres
```

普通减防按 0.9 上限处理，无视防御必须为 0..1；负抗不截断。输入 20 不会被猜成 20%，比例必须由调用方规范化。输出不做展示取整，保留 factors；浮点测试使用合理容差。

需要固定目标时用 `targetId` 绑定只读预设（当前仅 `dummy-lv100`：100 级、10% 全抗、无限血、静止）。等级或抗性与预设不一致直接拒绝，不能带着目标名字算别的数值；结果 `target` 回填目标身份，未绑定预设时 `target.id` 为 `custom`。

公式对照依据为原探索方案第8节的一般直伤公式，以及 [KQM Damage Formula](https://library.keqingmains.com/combat-mechanics/damage/damage-formula) 的公开机制说明。本轮未联网重新取证，不把外部链接存在当成已验证全版本例外。西风暴击触发产球等会改变后续状态的机制不在此 API 的期望暴击范围内。

固定检查包括同级防御 0.5、90级对100级防御 190/390、负抗/75%抗性边界、暴击溢出、ATK/HP/DEF及混合倍率；四个独立角色各自带自己的身份与白值，四类构筑包含4件套、2+2、散件与无运行时效果。它们只验证 P0 输入/算术/审计契约，不证明任何具体游戏角色的机制或实测伤害已正确。`legacyEstimate` 只断言口径标记，不证明旧聚合行的估算精度。
