# 轴编辑器（本地工具）

拼装 `data/team-sim/rotations/*.json` 的小服务，跑在维护者本机，**不进 Yunzai 插件进程**。

## 启动

```bash
node scripts/rotation-editor.mjs            # 默认 http://127.0.0.1:8791/
node scripts/rotation-editor.mjs --port 8800
node scripts/rotation-editor.mjs --open     # 起来后自动打开浏览器
node scripts/rotation-editor.mjs --check    # 不开服务，只跑自检
```

**双击快捷方式**：`scripts/open-rotation-editor.cmd`（Windows）。
已经在跑就直接开浏览器；没跑就后台起一个（最小化窗口）再打开页面。

本机已部署桌面快捷方式：`C:\Users\WIN11\Desktop\轴编辑器.lnk` →
指向 `cmd /c scripts\open-rotation-editor.cmd`，工作目录是仓库根。

页面在 `resources/editor-rotation/`（`index.html` + `app.js` + `style.css`，原生 JS，无依赖）。

## 能做什么

页面分两个页签：**① 拼一条轴**（默认）和 **② 从录制导入（进阶）**。默认视图只留普通玩家要的四步：

1. **选队伍**：四个位置，输入框里直接打字搜中文名（下拉候选来自 `data/team-sim/roster.json`）。
2. **排动作顺序**：每行 = 角色 + 中文动作名（`普通攻击 第1段` / `元素战技` / `元素爆发`）+ 时长；
   「＋ 加爆发（能量够了才放）」会写成 `{ "actionId": "...", "optional": true }`，能量不够时内核跳过这一次。
3. **充能效率**（可选）：按人填，缺省 100%；产球按全队共享结算。
4. **检查并保存**：报错会翻成中文（例如「这一步能量或冷却不够」），原始 `path` 收在「高级设置」里。

「高级设置（一般不用动）」折叠着轴 id、JSON 预览、窗口与循环开关；轴 id 会用队伍自动生成，可手改。

**录制导入**：选好队伍后，页面生成可直接复制的 `python scripts/record-keys.py ...` 命令；把录制器输出的
JSON 粘进来，服务端会做归一化（`normal-1 / skill / burst / switch:N` → 绝对键，切人后动作算到当时前台），
顺带生成键位表并校验，通过后保存成同目录的轴文件。

## 面板与词条（从 miao / bot 导出）

「面板与词条」页签可以手填，也可以从 miao 读：

1. **读取导出（推荐，与 `#练度查询` 完全同一路径）**
   在群里发 `#练度查询 <角色> 导出`：bot 用消息事件里的米游社绑定 → miao `Player` → `avatar.getArtisDetail()`
   取面板，写到 `data/team-sim/panel-exports/<charId>.json`；页面里点角色卡上的「读取导出」即可载入。
   这条路不开端口、不另存账号，账号口径与查询命令一致。
2. **从 miao 读取（本地缓存）**
   直接列 `data/PlayerData/gs/*.json` 的缓存 uid，选一个再点角色卡上的「从 miao 读取」。
   只读本地缓存、不联网刷新；uid 是手选的，不等同于「查询时用的那个 QQ 的绑定」。

两条路都会把武器、五件圣遗物的套装/主词条/词条档位自动填好；4 星主词条按 5 星表近似，界面上有提示。

## 校验口径

- 动作必须在对应角色的动作包里，且 `actorId` 与动作归属一致；
- 队伍里的 charId 必须能在名录里找到动作包；
- 窗口内排不出动作、事件顺序非法等，直接列出 `path: message`；
- 保存成功返回固化成固定轴后的动作数、步骤数与最后一帧。

## HTTP 接口（给页面用，也可以脚本调）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/roster` | 名录（charId、中文名、动作包键、动作数） |
| GET | `/api/actions?key=bennett` | 该角色动作列表 |
| GET | `/api/rotations` | 已入库的轴文件 |
| GET | `/api/rotation?id=xxx` | 单份轴 |
| POST | `/api/validate` | `{ file }` 只校验 |
| POST | `/api/import-recording` | `{ recording, id }` 录制归一化 + 生成键位表 + 校验 |
| PUT | `/api/rotation` | `{ file }` 校验通过后写 `data/team-sim/rotations/<id>.json` |

写入只允许 `<id>.json` 这种安全文件名（字母数字、点、下划线、短横线），不允许写到目录外。

## 边界

- 只写「动作顺序轴」；精确帧、录制轴仍按 `docs/队伍模拟-轴文件格式.md` 手写。
- 不做增删角色名录、不生成动作包（那是 `scripts/gen-roster-packs.mjs` 的事）。
- 只在维护者本机用，依赖仓库里的 `lib/` 编译产物，所以改过 `src/` 要先 `pnpm build`。
