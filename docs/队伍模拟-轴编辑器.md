# 轴编辑器（本地工具）

拼装 `data/team-sim/rotations/*.json` 的小服务，跑在维护者本机，**不进 Yunzai 插件进程**。

## 启动

```bash
node scripts/rotation-editor.mjs            # 默认 http://127.0.0.1:8791/
node scripts/rotation-editor.mjs --port 8800
node scripts/rotation-editor.mjs --check    # 不开服务，只跑自检
```

页面在 `resources/editor-rotation/`（`index.html` + `app.js` + `style.css`，原生 JS，无依赖）。

## 能做什么

1. **选队伍**：从 `data/team-sim/roster.json` 里挑最多四人（按 charId 记，保存时写进 `team`）。
2. **拼动作顺序**：每行一个动作，下拉里只列该角色动作包里真正存在的 id；可以上移/下移/删除。
3. **可选爆发**：勾「可选」或点「＋ 可选爆发」，写成 `{ "actionId": "bennett.burst", "optional": true }` ——
   能量不够时内核会跳过这一次、继续排后面，不会把整份轴判死。
4. **充能效率**：按人填 `energyRecharge`（缺省 1.0），产球按全队共享结算。
5. **窗口与循环**：默认 7243 帧（60 档标准窗口）、`loop: true`。
6. **校验与保存**：保存前用内核同一套 `TeamSimStore.toRotation()` 校验；不通过就只显示问题、不落盘。

## 校验口径

- 动作必须在对应角色的动作包里，且 `actorId` 与动作归属一致；
- 队伍里的 charId 必须能在名录里找到动作包；
- 窗口内排不出动作、事件顺序非法等，直接列出 `path: message`；
- 保存成功返回固化成固定轴后的动作数、步骤数与最后一帧。

## HTTP 接口（给页面用，也可以脚本调）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/roster` | 名录（charId、中文名、动作包键、动作数） |
| GET | `/api/actions?key=bennett` | 该角色动作列表 |
| GET | `/api/rotations` | 已入库的轴文件 |
| GET | `/api/rotation?id=xxx` | 单份轴 |
| POST | `/api/validate` | `{ file }` 只校验 |
| PUT | `/api/rotation` | `{ file }` 校验通过后写 `data/team-sim/rotations/<id>.json` |

写入只允许 `<id>.json` 这种安全文件名（字母数字、点、下划线、短横线），不允许写到目录外。

## 边界

- 只写「动作顺序轴」；精确帧、录制轴仍按 `docs/队伍模拟-轴文件格式.md` 手写。
- 不做增删角色名录、不生成动作包（那是 `scripts/gen-roster-packs.mjs` 的事）。
- 只在维护者本机用，依赖仓库里的 `lib/` 编译产物，所以改过 `src/` 要先 `pnpm build`。
