# 队伍模拟 · 轴文件格式（手写版）

`#队伍伤害` 只认 `data/team-sim/rotations/*.json` 里的轴文件；没有轴就不给数字。
本文件说明如何**手写**一份轴，以及校验规则。

## 1. 文件位置与命名

- 目录：`data/team-sim/rotations/`
- 命名：随意，建议 `<队伍简述>.json`（如 `geo-four.json`）
- 一份文件 = 一支固定四人队伍（`team` 数组按 charId 全等匹配，顺序无关）
- 同队多份时取文件名排序第一份，并在结果里提示

## 2. 结构

```jsonc
{
  "schemaVersion": 1,
  "id": "geo-four-basic",          // 轴的稳定 id
  "team": ["10000057", "10000055", "10000038", "10000030"], // 四人 charId
  "measurementEndFrame": 7243,      // 测量窗口终点（fps-60 档 120 秒 = 7243 帧）
  "scheduler": "fixed",             // fixed | asap-sequence，默认 fixed
  "keymap": {
    "version": "geo-four-v1",       // 必须与 recording.keymapVersion 一致
    "bindings": {
      "zhongli.skill": { "actorId": "zhongli", "actionId": "zhongli.skill" },
      "to_albedo":     { "actorId": "albedo",  "switch": true }
    }
  },
  "recording": {
    "schemaVersion": 1,
    "frameTierId": "fps-60",
    "keymapVersion": "geo-four-v1",
    "gameVersion": "7.1",
    "source": "handmade",
    "start": {
      "activeActorId": "zhongli",
      "actors": [
        { "actorId": "zhongli", "energy": 0, "energyMax": 40 }
      ]
    },
    "events": [
      { "atMs": 0, "key": "zhongli.skill", "phase": "down" },
      { "atMs": 32, "key": "zhongli.skill", "phase": "up" }
    ]
  }
}
```

## 3. 关键约束

| 约束 | 说明 |
|---|---|
| `actorId` 用**动作包里的角色键** | 如 `zhongli`，不是 charId `10000030` |
| `team` 用 **charId** | 目录匹配按 `build.characterId` 全等 |
| 事件时间戳单调不减 | 排序后再写入，同一毫秒可有多条 |
| `measurementEndFrame` 必须大于最后一步帧号 | 否则最后一段不结算 |
| 标准口径必须 120 秒窗口 | fps-60 = **7243 帧**；否则 DPS 标准校验会拒绝 |
| 动作必须在**前台角色**发起 | 换人用 `{ "switch": true }` 绑定 |
| 换人/取消要满足取消窗 | `fixed` 调度下帧号不成立会报「早于最早可取消帧」 |

`atMs` 换算：`atMs = round(frame × 1000 / fps)`，fps-60 档 `fps = 60.36144`。

## 4. 校验流程

命令会依次检查：

1. `validateRecording`：schemaVersion、四项元数据、起手锚点、时间戳单调
2. `recordingToRotation`：键位表版本一致、键都有绑定、帧号换算
3. `validateRotation`：动作存在、归属正确、换人时机、测量窗口

任何一步失败都只回「差在哪」，不会拿 0 或猜测值顶上。

## 5. 示例

`data/team-sim/rotations/geo-four.json`：钟离战技 → 阿贝多战技 → 一斗战技 + 普攻 1–4 → 五郎战技，
共 11 步，窗口 7243 帧（120 秒），用于验证通路。

## 5.1 顺序轴（2026-11-02 起，手写首选）

没有编辑器时不用写时间戳：只写**动作顺序**，帧由调度器排。文件里用 `sequence` 代替 `recording + keymap`：

```jsonc
{
  "schemaVersion": 1,
  "id": "demo-skill-sequence",
  "team": ["10000023", "10000025", "10000032", "10000060"],
  "measurementEndFrame": 7243,
  "scheduler": "asap-sequence",   // 顺序轴固定用这个
  "frameTierId": "fps-60",
  "sequence": [
    "bennett.skill", "xiangling.skill", "xingqiu.skill", "yelan.skill",
    "bennett.normal-1", "bennett.normal-2"
  ]
}
```

- `actorId` 默认取动作 id 的点号前缀（动作包键，如 `bennett`）；也可以写 `{ "actionId": "...", "actorId": "..." }` 覆盖；
- **角色变化时自动插切人步骤**，不用手写 `to_xxx`；
- 初始能量缺省 0，上限按该角色爆发能耗推；要指定就加 `"actors": [{ "actorId": "bennett", "energy": 80, "energyMax": 80 }]`；
- 读入时先按 `asap-sequence` 排一遍，再把实际帧**固化成 fixed 轴**（机制规划目前只认 fixed），所以结果里每一步都有帧；
- 示例文件：`data/team-sim/rotations/demo-skill-sequence.json`（13 条动作，四人战技 + 普攻）。

顺序轴的取舍：它按「上一个动作结束、到可取消帧就切」来排，不表达精确的卡肉/取消窗操作；
要做逐帧复现的竞速轴还是得用录制轴。

## 6. 常见报错

| 报错 | 原因 |
|---|---|
| `动作包里没有 xxx` | actionId 拼错，或该角色还没有对应动作数据 |
| `动作 x 属于 y，不能由 z 发起` | `actorId` 写成了 charId 或别的角色键 |
| `换人请求帧 N 早于上一动作最早可取消帧 M` | 上一段动作还没到取消窗，帧号要往后推 |
| `时间戳必须单调不减` | events 没排序，或 `up` 的时间早于同段 `down` |
| `DPS 标准窗口是 120 秒…实际 N` | `measurementEndFrame` 不是 7243（fps-60） |
| `轴文件要么给 sequence，要么给 recording + keymap` | 两种写法混了或都没写 |
| `… 属于 bennett，但 actorId 写成了 xiangling` | 顺序轴里显式覆盖 `actorId` 时写错归属 |
