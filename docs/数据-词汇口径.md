# 文档词汇 vs 显示词汇


仓库里有**两套词汇表**。它们不是重复劳动，是分工；搞混会**直接破坏 129/129 文档往返**。

| | 文档词汇（**源**，必须原样保留） | 显示词汇（**呈现**，只由显示层产出） |
|---|---|---|
| 档位 | 武器：`第一档` / `第二档` / `第三档`；圣遗物与配队：`推荐` / `可选` / `过渡`（2026-09-30 起**文档词就是显示词**，旧写法 `首选` / `次选` / `套装` 仍能读回，属兼容别名）；**`label` 非空 = 自定义档位词**（如 `建议`，见 [档位词自定义](./数据-档位与攻略图.md)） | `推荐` / `可选` / `过渡`（**三档**，第三档为空时整行不渲染） |
| 命座 | `二命——说明` | `命之座2` |
| 天赋行标签 | `天赋：A1 E10 Q10`（文档里的行首词） | **没有行首标签**（`label: ''`，用户定稿 2026-09-21 去掉「推荐」chip；天赋只有 A/E/Q 三格，图标已自明。判行要用 `kind === 'talents'`，别按文字判；空标签的行两端都按「无标签行」铺满整行） |
| 段落标题 | `1. 武器推荐` / `4. 毕业面板参考` / `5. 命座推荐` / `6. 配队推荐` | `武器` / `圣遗物` / `天赋` / `面板` / `命座` / `配队` |
| **主词条** | `攻击力` / `生命值` / `防御力` / `元素精通` / `元素充能效率` / `暴击率` / `暴击伤害` / 各元素伤害加成 —— **不写「百分比」**（主词条默认就是百分比；旧写法 `攻击力百分比` 已全部改掉） | 原样（主词条不做简写） |
| **副词条** | 百分比 = `大生命` / `大攻击` / `大防御`；固定值 = `小生命` / `小攻击` / `小防御`（旧写法 `生命值百分比` / `攻击力` 已全部改掉） | **`大X` / `小X` 本身就是显示形态**（不再展开成 `生命值`/`攻击力`/`防御力` —— 那是"固定值"语义，会弄错） |
| 圣遗物件数 | **不写** `（2件套）`（旧写法已全部改掉）；2+2 写**属性词简写**：`2精通 + 2精通`、`翠绿之影 / 2攻击`、`昔日宗室之仪 / 2生命 + 2充能 + 角斗士的终幕礼`（`2攻击` / `2生命` / `2精通` / `2充能` 是编辑器预设，已进索引白名单，见 [脚本：解析告警](./脚本-解析告警.md) 的「名称校验问题」） | 件数**不渲染**（网页版 / 面板都不画；`parseSetItem` 仍容错读取，旧数据往返不丢）；`2X` 里的词条**不再展开**（`2充能` 保持 `2充能`，不会变成 `2元素充能效率`） |
| **毕业面板** | `属性：数值` 一行一条；有标签时写 `标签：属性：数值`（一行两个冒号 ⇒ 回读是说明行）。属性只用七种规范词（`充能效率` / `充能` / `暴伤` 这些历史写法已全部改掉）；数值**不带尾部的 `+`**，百分比属性带 `%`（`暴击率：70%`、`攻击力：2200`） | 属性行原样；同标签 ≤3 条合并成一行（行间全角空格），面板 / 网页版 / 编辑器三处同口径 |
| 其它简写 | `充能` / `精通` / `暴伤` / `爆伤` / `大公鸡` … | `元素充能效率` / `元素精通` / `暴击伤害` / `攻击力` … |
| 固定术语 | `双爆` | `暴击率=暴击伤害`（**同级**，恒等；只作词条时才展开，散文里原样） |
| 出现位置 | 主文档 docx、`data/gi/*.json` 的 `v2.*.label` 与 `sections[].*`、`guide.md` | `guide.html`、插件面板、编辑器预览 |

**符号语义（用户定稿，四处一致）**：`=`（显示 `＝`）**同级/等价**；`/` **或者/可替换**；
`>`（显示 `＞`）**优先级/顺序**；`≥` 保留原样。`｜` 只用于主词条三个**槽位**之间的并列。

**副词条的特例（用户定稿，最容易搞错的一条）**：副词条里**只有「暴击率 ↔ 暴击伤害」是同级**，
其余相邻词条一律是优先级。**显示规则与源文档写什么无关**（写 `/` 还是 `>` 都一样）：

```text
文档：副词条：暴击率 / 暴击伤害 > 大攻击 > 元素精通     文档：副词条：元素精通 > 暴击率 > 暴击伤害
显示：副词条：暴击率 = 暴击伤害 ＞ 大攻击 ＞ 元素精通   显示：副词条：元素精通 ＞ 暴击率 = 暴击伤害
```

- 暴击对**恒为 `=`**（`≥` 是显式写法，原样保留）；
- 其余相邻词条**恒为 `＞`** —— 就算源文档写了同级 `/`，也照样显示 `＞`；
- 判据是**显示文本**（`暴击` / `暴伤` 已展开成 `暴击率` / `暴击伤害`），由 `subSepBetween` 实现。

**不要在非暴击对之间写 `/`**（显示层会兜底成 `＞`，但文档读起来会误导）：
`scan-separators.mjs` 会把非法同级对当错误拦下来。

**副词条逐档分隔符**：`v2.artifacts[kind=sub].sep` 按**空白分隔的逐档 token** 存
（`' / > > '` ＝ 第 1 档 `/`、第 2/3 档 `>`）；`parse-docx` 的 `gapSepOf` 生成、
`schema.renderArtifactRow` 的 `sepTokens` 逐字写回。所以一行里可以混用 `/` 与 `>`。

**圣遗物套装的分隔符（用户定稿，2026-09-20 二次修订）**：源文档里的 `/` 是**同级**（"这套或那套都行"）→
显示成**字面 `/`**（`教官/勇者`、`翠绿之影/2攻击`）；`>` / `≥`（优先级）才画 `＞`。
`+` **只有两侧都是件数简写（`2X`/`4X`）时**才算「同一组合」（2+2 才凑得满 4 件）→ 留在**同一个 chip 内**；
**全套装名之间的 `+` 其实是同级选项 → 显示 `/`**（用户原话：「同级圣遗物套装之间依旧有部分角色为 `+` 而不是 `/`」）。
见 `guide-display.mjs` 的 `SET_LEVEL_SEP` / `gapSepOf` / `isPieceShorthand` / `resolveSetItems`：

```text
文档：推荐：教官 / 烬城勇者绘卷        →  显示：[教官]/[烬城勇者绘卷]     （同级：字面 `/`）
文档：推荐：如雷的盛怒 + 昔日宗室之仪   →  显示：[如雷的盛怒]/[昔日宗室之仪]（全名之间：同级）
文档：过渡：2精通 + 2精通             →  显示：[2精通+2精通]           （2+2：同一 chip）
文档：推荐：2生命 + 2充能 + 角斗士…    →  显示：[2生命+2充能]/[角斗士…] （简写组合 vs 同级）
文档：推荐：A套 > B套                 →  显示：[A套]＞[B套]            （优先级）
```

**2+2 一律写简写（用户定稿 2026-09-30）**：「今后添加 2+2 后自动改为简写，不再写全称」。
`+` 连接的**恰好两条**就是 2+2，两条一律写成 `2X + 2Y`：

- **2 件套效果等于四条通用预设的**（攻击 18% / 生命 20% / 精通 80 / 充能 20%）写预设词：
  `角斗士的终幕礼 + 千岩牢固` → `2攻击 + 2生命`；
- **其余**写社区通用的**套装简称**（`TWO_PIECE_ABBR`，源头是 `scripts/lib/schema.mjs` 的 `ARTIFACT_2PC`）：
  `染血的骑士道 + 冰风迷途的勇士` → `2染血 + 2冰套`。
  已定的简称：魔女 / 渡火 / 如雷 / 平雷 / 宗室 / 少女 / 苍白 / 染血 / 冰套 / 水套 / 水仙 / 风套 /
  磐岩 / 流星 / 海染 / 华馆 / 草套 / 剧团 / 猎人 / 长夜 / 昔时 / 黑曜 / 勇者 / 楼阁 / 深廊 /
  天美 / 武人 / 战狂（**表里没有的套装不硬凑**，扫描会提醒补一行）。
**四条预设优先，且判定要跟图鉴对齐**：`node scripts/audit-2pc-table.mjs` 会读图鉴后端每个套装的
2 件套描述，按**定稿数值**判定（攻击力 18% / 生命值 20% / 元素精通 80 / 元素充能效率 20%），
与 `schema.mjs` 的表比对并列出「没判定、也没简称」的套装。当前 0 不一致；
`影中沉凝的幻灭`、`血红之证` 的 2 件套就是攻击 → `2攻击`（用户 2026-09-30 更正：有常用预设的以预设为准）。

自动改写发生在两处：`parse-docx`（文档里写了全名也当场改掉，回写就是简写）与编辑器保存
（`editor.mjs` 的 `normalizeV2`）；编辑器里两件之间的 `/` ↔ `+` 可切，切成 `+` 时界面当场改写
（`app.js` 的 `shortenRowTwoPiece`）。**三条的 `+` 组合不动** —— `2生命 + 2生命 + 教官` 里第三套
其实是 4 件套选项，三条简写会被并成一个 chip（＝ 6 个部位）。

**圣遗物「同级」条数上限（用户定稿 2026-09-30）**：一行最多 **3 种带法**（`+` 组合算一种），
武器行最多 **4 把**。编辑器点「＋」越过上限会**直接挡下**并提示；`scan-separators.mjs` 会把老数据
里超标的行列出来（只提醒，不影响退出码）。

**主词条 / 副词条的括注：统一写在「值里」**（用户定稿 2026-09-20）

写法就一种 —— 括注跟在**那个具体值**后面、且只出现在**值末尾**：

```text
数据：理之冠：防御力（特殊）        →  显示：[理之冠：防御力] + 小字「（特殊）」
数据：副词条：暴击（西风）          →  显示：[暴击率] + 小字「（西风）」
数据：空之杯：水元素伤害加成（二命）  →  显示：[空之杯：水元素伤害加成] + 小字「（二命）」
```

- **为什么选值里（而不是 `note` + `noteSlot` 字段）**：文档就是这么写的（`防御力（特殊）`），
  数据与文档**同形** → `doc→JSON→doc` 逐字相等；括注天然跟着那个值，不需要 `noteSlot` 回指，
  也不会有「一行只能写一条括注」的限制。字段形式是**历史写法**，显示层仍兼容（见下），但**不再新增**。
- **剥离逻辑只有一份**：`guide-display.mjs` 的 `splitStatNote(value) → {text, note}`
  （只认末尾那一层括号，与 `parse-docx` 的 `NAME_NOTE_RE` 同判据）。
  显示层在**判分隔符之前**先剥括注（`暴击率（西风）` 得先认出是 `暴击率`，才判得出它是暴击对）；
  两条链路（网页版 / 面板）都走同一个 `normalizeArtifactRows`。
  凡是要**按值精确匹配**的新代码（候选表 / 别名归一 / 审计比对）也都要先过这个函数。
- **历史字段写法**（`kind:'main'` 的 `note` + `noteSlot`）仍能正确显示（网页版与面板都会把它
  挂到对应部位的小字备注上），但迁移已把数据折回值里：迁移脚本是维护者本地的 `本机脚本 normalize-main-notes.mjs`（不入库，本仓库不存在）。
- `scan-separators.mjs` 会检查「括注只在值末尾」（写在中间会被分隔符逻辑切开 → 文档与数据漂移）。

**武器行的分隔符（用户定稿：正常武器用 `＞`）**：武器档位是**优先级链**，所以**源文档写 `/` 也显示 `＞`**：

```text
文档：满拐：岩峰巡歌 / 圣显之钥        →  显示：[岩峰巡歌]＞[圣显之钥]
```

「**同级且毫无区别**」的写法有两种：

- **一个条目里用 `\` 列多把**（用户定稿 2026-10-04：**`\` 与 `=` 等价**）——例：玛拉妮的
  `遗祀玉珑\千夜浮梦`、瓦雷莎的 `鹤鸣余音\四风原典\神乐之真意\天空之卷`。
  渲染层（网页版 / 面板）显示成 `遗祀玉珑 = 千夜浮梦`，与档位箭头 `＞`（优先级）明确区分；
  校验（`validate`）按 `\` 拆开**逐个部件**去图鉴里核对，只报真正缺失的那一把。
  ⚠ 只替换**渲染文本**：主文档行与 `guide.md` 保留作者写的 `\` —— `parse-docx` 按 `=` 会把
  一个条目拆成多条（条数与同级上限都会变），文字层不能替换。
- **名字里带 `/`**（例：`88爆伤/44暴击武器`，两把武器同级、没区别）：`/` 是名字的一部分，
  原样保留、不会被当分隔符。⚠ 但 `/`、`｜` 在写回文档后再解析会被切成两条（往返不一致）——
  编辑器会打 ⚠、`scan-separators` 也会列出来；这种写法请改用 `\`（等价候选），
  或拆成两条用 `/` 相连（`88爆伤 / 44暴击武器`）。

**为什么 `v2.label` 里必须留着档位词（`推荐` / `可选` / `过渡` / `第一档`）：**

- `parse-docx.mjs` 的行首档位正则认 `推荐|首选|次选|可选|过渡|套装`（**2026-09-30 起 `推荐/可选/过渡` 就是文档词**，
  `首选` / `次选` / `套装` 保留为兼容别名，旧文档与旧 JSON 照旧读得回来）；
  小节标题只认 `武器推荐` / `毕业面板参考` 这些**长标题**，不认 `面板`。
- 所以 `docx → JSON → docx` 往返（硬验收 **129/129 深度相等**）依赖这些文档词**逐字存在**。
- 显示词与文档词**现已同名**（`推荐` / `可选` / `过渡`），但仍由 `scripts/lib/guide-display.mjs` 的
  `displayTitle` / `displayLabel` / `TIER_BY_INDEX` / `constellationNumber` / `STAT_ALIASES`
  在**渲染期**换算，**一个字都不写回 JSON / docx**。

> ⚠ **改落盘词的正确顺序**：先改 `parse-docx` 的识别规则 → 再改文档与数据 → 最后才改落盘词。
> （2026-09-30 的 `首选`→`推荐` 就是按这个顺序做的：先给 `parse-docx` 加 `推荐`，再批量改数据 + 回写主文档。）
> 反过来做的话，`build-docx --write-main` 写出的文档无法被 `parse-docx` 读回 ——
> 该行会掉进 `unparsed`，往返校验立刻**不再是 129/129**。
